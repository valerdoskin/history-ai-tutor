# Промт: Показ исторических карт в вопросах (map)

> **Дата:** 2026-09-02
> **Цель:** чтобы в вопросах с картой (тип `map`) ученик видел **саму карту (изображение)**,
> а не только её текстовое описание. Сейчас карта не показывается вовсе.

---

## Проблема (диагноз уже поставлен, НЕ перепроверять)

Вопросы типа `map` генерируются из справочника `knowledge/maps.json` (188 записей) функцией
`generate_map_question()` в `services/exam_service.py`. Сейчас:

- В `maps.json` у каждой записи **НЕТ поля с изображением** — только текстовые поля:
  `name, period, class, description, key_objects, fipi_codes, source_chunk_id`.
- `generate_map_question()` строит вопрос по текстовому `description` и **не передаёт
  изображение**. Вопрос выглядит так: «На исторической карте показано: [текст описания]...
  Какое событие изображено на карте?» — но самой карты ученик не видит.
- Фронтенд (`static/webapp.js`) **не имеет логики отображения изображений** — рендерит только
  текст вопроса и варианты ответа.
- В проекте **нет ни одного файла изображения** (папка `static/` содержит только `webapp.css`
  и `webapp.js`).

Это не соответствует реальному формату ОГЭ/ЕГЭ, где в задании даётся именно **изображение карты**.

## Исходные данные (что уже есть)

- Исходные учебники лежат в `books/` — для каждого есть **DOCX и парный PDF**
  (например `Istoriya_Rossii_10kl_2023.docx` + `Istoriya_Rossii_10kl_2023.pdf`).
- В PDF-учебниках есть изображения (карты + иллюстрации). Извлечение изображений из PDF
  технически возможно через `pdfplumber` (установлен) — у изображений есть координаты и размеры.
- Каждая запись `maps.json` ссылается на чанк через `source_chunk_id`, а чанк в
  `knowledge/chunks.json` содержит `source_file` (какой учебник) и поля `page_start`/`page_end`.
- **ВАЖНОЕ ОГРАНИЧЕНИЕ:** только **2 из 188** записей `maps.json` ссылаются на чанк с известной
  страницей (`page_start`). Для остальных 186 точная страница в учебнике неизвестна — её нужно
  определить (см. ниже).
- Распределение записей по учебникам (`source_file`): Istoriya_Rossii_10kl_2023.docx — 67,
  Za_8_klass.docx — 24, Vseobschaya_10.docx — 21, 7_klass._Istoriya_Rossii.docx — 18,
  Za_9_klass.docx — 17, 6_klass._Istoriya_Rossii.docx — 15, 5_klass_Istoriya_Drevnego_mira_.docx — 12,
  остальные — меньше.

## Варианты решения (выбрать и согласовать с пользователем)

### Вариант A (рекомендуемый): извлечь карты из PDF-учебников
- Извлечь изображения карт из PDF-версий учебников, сохранить в `static/maps/`, добавить в
  каждую запись `maps.json` поле `image` (путь к файлу), обновить генератор и фронтенд.
- **Плюсы:** карты настоящие, из учебников (соответствует принципу «только локальная база»).
- **Минусы:** трудоёмко; нужно (1) найти страницу с нужной картой для каждой из 188 записей,
  (2) отличить карту от иллюстрации/фото на странице, (3) обрезать/сохранить нужное изображение.

### Вариант B: программный рендер схематичных карт (SVG/Canvas)
- Строить упрощённые схемы по данным `maps.json` (`key_objects`, направления).
- **Минусы:** сложно и неточно для реальных исторических карт; не соответствует формату экзамена.

### Вариант C: внешние источники карт
- **НЕ подходит** — противоречит принципу проекта «без внешних источников».

### Вариант D: улучшить подачу текстового описания (без изображения)
- Показывать описание карты как «источник» (как в source-вопросах). Не решает проблему
  отсутствия самой карты, но улучшает читаемость. Может быть временным решением.

## Что нужно сделать для Варианта A (если он выбран)

### Шаг 1. Определить страницы карт в учебниках
Для каждой записи `maps.json` нужно найти страницу в соответствующем PDF-учебнике, где
находится эта карта. Способы:
- Использовать `source_chunk_id` → чанк → `page_start` (работает только для 2 записей).
- Для остальных: сопоставить название карты (`name`) с текстом параграфа/подписью к рисунку
  в PDF. Подписи к картам в учебниках обычно вида «Карта. <название>» или «Рис. N. <название>».
- **Нужна ручная/полуавтоматическая проверка** — автоматически надёжно определить страницу
  для всех 188 карт нельзя.

### Шаг 2. Извлечь изображения карт из PDF
- Скрипт на `pdfplumber`: для заданной страницы извлечь крупные изображения
  (карты обычно крупные и широкие, например `width > 200` и `height > 150` pt).
- Сохранить как PNG/JPG в `static/maps/<id>.png` (id — ключ записи maps.json).
- Отфильтровать не-карты (иллюстрации, фото, декоративные элементы) — по размеру/пропорциям
  и/или ручной проверке.

### Шаг 3. Обновить maps.json
- Добавить каждой записи поле `image` (например `"/static/maps/<id>.png"`).
- Для записей, где карту найти не удалось, оставить `image: null` (вопрос будет без карты).

### Шаг 4. Обновить генератор (services/exam_service.py)
- В `generate_map_question()` добавить в возвращаемый объект поле `image` из записи maps.json
  (если есть). Вопрос должен ссылаться на карту, а не только на текст описания.

### Шаг 5. Обновить фронтенд (static/webapp.js + static/webapp.css)
- В рендере вопроса (функции `renderTrainQuestion`, рендер полного теста и т.д.) при наличии
  `q.image` выводить `<img src="..." class="map-image">` перед текстом вопроса.
- Добавить CSS-класс `.map-image` (адаптивная ширина, `max-width: 100%`, рамка).
- Убедиться, что карта корректно отображается на ПК и мобильном (см. PROMPT_RESPONSIVE_UI.md).

### Шаг 6. Проверка
- Сгенерировать map-вопросы для разных классов — карта должна отображаться.
- Проверить в браузере на ПК и мобильном.
- Убедиться, что записи без карты (`image: null`) не ломают рендер.

## Критерии приёмки

1. В вопросах типа `map` ученик видит изображение карты (для записей, где карта найдена).
2. Карты взяты из учебников (локальная база), без внешних источников.
3. `maps.json` обновлён (поле `image`), JSON валиден.
4. Фронтенд корректно показывает карту на ПК и мобильном, не ломая другие типы вопросов.
5. Записи без найденной карты не вызывают ошибок.

## Правила против зацикливания

- НЕ перечитывай `maps.json`/`chunks.json`/PDF повторно после начала работы — работай по
  уже известной структуре (диагноз выше).
- НЕ пытайся автоматически найти страницу для всех 188 карт за один проход — это требует
  ручной проверки. Сначала сделай пилот на 5-10 картах, покажи результат пользователю.
- НЕ меняй логику других типов вопросов (culture, source, argumentation и т.д.).
- После пилота согласуй с пользователем, продолжать ли для всех 188 карт.
