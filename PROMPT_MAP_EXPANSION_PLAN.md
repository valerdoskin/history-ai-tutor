# Промт-план: расширение количества карт с изображениями (186 из 188)

## Правила против зацикливания (читать ПЕРЕД началом работы)

1. **Один шаг за раз.** Выполняю ровно один шаг процесса, затем останавливаюсь и сообщаю
   результат пользователю. Не перехожу к следующему шагу без явного подтверждения.

2. **Не повторяю одно и то же действие.** Если действие уже выполнено и дало результат,
   не выполняю его снова. Если результат не изменился после 2 попыток — останавливаюсь
   и спрашиваю пользователя.

3. **Не задаю один и тот же вопрос дважды.** Если пользователь уже ответил на вопрос,
   использую его ответ и двигаюсь дальше. Не переспрашиваю.

4. **Критерий завершения шага.** Каждый шаг считается завершённым, когда получен
   конкретный результат (файл создан, данные обновлены, ответ получен). После этого
   шаг помечается как «выполнено» и больше к нему не возвращаюсь.

5. **Точка остановки для вопроса пользователю.** Останавливаюсь и спрашиваю пользователя
   только в двух случаях:
   - (а) нужен ответ человека на промт-задание (где находится карта);
   - (б) возникла неоднозначность, которую нельзя разрешить автоматически.

6. **Не исследую без цели.** Каждое действие (bash, чтение файла) должно приближать
   к конкретному результату текущего шага. Не выполняю «исследовательские» команды,
   которые не нужны для текущего шага.

7. **Фиксирую прогресс.** После каждого завершённого шага кратко записываю, что сделано
   и что будет дальше. Это помогает не повторяться.

## Цель

В базе `knowledge/maps.json` — 188 записей о картах. Сейчас только **2 записи** имеют поле
`image` (greek_colonization.png, alexander_macedon.png). Задача — добавить изображения карт
для **оставшихся 186 записей**, извлекая их из PDF-учебников в `books/`.

**Уже обработаны (исключены из плана):**
- «Великая греческая колонизация» → `static/maps/greek_colonization.png`
- «Походы Александра Македонского на Восток» → `static/maps/alexander_macedon.png`

Эти 2 карты уже имеют поле `image` в maps.json, поэтому они **не входят** в список 186 записей
для обработки и не должны повторно определяться.

## Ключевые принципы (подтверждены пользователем)

1. **`.docx` и `.pdf` — одна и та же версия учебника в разных форматах.** В `chunks.json`
   `source_file` указывает на `.docx`, а PDF-учебник в `books/` имеет то же имя с расширением
   `.pdf`. Связь — простая замена расширения `.docx` → `.pdf`.

2. **Карта привязана к параграфу учебника.** Все 188 записей maps.json имеют `source_chunk_id`,
   который точно совпадает с `id` чанка в `chunks.json`. По `source_chunk_id` находим чанк,
   а по его `paragraph_title` и `source_file` — собираем весь текст параграфа. Вопрос LLM
   должен соответствовать описанию параграфа.

3. **Автоматический анализ (цвета + OCR) НЕ может надёжно отличить карты от иллюстраций.**
   Поэтому нужна **ручная проверка человеком** отрендеренных страниц.

## Процесс (для каждой записи maps.json без image)

Процесс выполняется **по одному PDF-файлу за раз**. Для каждого PDF-файла выполняются
шаги 1–3 (автоматически), затем останавливаюсь и передаю промт-задание человеку (шаг 4).
После ответа человека выполняю шаги 5–7.

### Шаг 1. Определить страницы параграфа (автоматически)
- По `source_chunk_id` найти чанк в `chunks.json`.
- По `source_file` чанка определить PDF-файл в `books/` (замена `.docx` → `.pdf`).
- Извлечь текст всех страниц PDF и найти страницы, где встречается `paragraph_title`.
  **Результат:** для каждой записи — диапазон страниц параграфа.
- **Критерий завершения:** получен список «запись → страницы» для всех записей текущего PDF.

### Шаг 2. Отрендерить страницы в `map_preview/` (автоматически)
- Для каждой страницы диапазона отрендерить PNG (957×1252 px).
- Именование: `<slug>_p<номер>.png`.
- **Критерий завершения:** все PNG созданы в `map_preview/`.

### Шаг 3. Создать промт-задание для человека
- Для каждой записи указать: страницы, файлы для просмотра, ключевые объекты карты.
- **Критерий завершения:** промт-задание готово и показано пользователю.

### Шаг 4. Человек указывает страницу и область карты (остановка)
- **Здесь останавливаюсь и жду ответа человека.** Не продолжаю дальше автоматически.
- Человек смотрит изображения и отвечает: карта найдена ДА/НЕТ, страница, область в %.

### Шаг 5. Вырезать карту и сохранить (после ответа человека)
- По указанной области вырезать карту из отрендеренной страницы → `static/maps/<slug>.png`.

### Шаг 6. Обновить maps.json
- Добавить поле `image: "/static/maps/<slug>.png"` в запись maps.json.

### Шаг 7. Сгенерировать вопрос через LLM
- Запустить `scripts/pregen_map_questions.py` для записей с image → `question_bank.json`.

## Формат промт-задания для человека (аналогично PROMPT_MAP_PREVIEW.md)

Для каждой записи:

```
<N>. <Название карты> (класс <N>)
   - Карта найдена: ДА / НЕТ
   - Страница(ы) PDF: <номер страницы>
   - Область карты на странице (примерные координаты в % от ширины/высоты страницы):
     x: от <..>% до <..>%, y: от <..>% до <..>%
   - Комментарий: <что изображено, есть ли подпись к карте>
```

## Примечания

- Если на странице несколько изображений (карта + иллюстрации), указать, какое именно
  изображение является картой.
- Если карта занимает всю страницу или её большую часть, так и указать.
- Если карты в параграфе нет, указать «НЕТ» — это тоже полезная информация.
- Координаты области нужны, чтобы вырезать карту без лишнего текста.
- После каждого PDF-файла запускать `pregen_map_questions.py` для генерации вопросов
  по добавленным картам.
