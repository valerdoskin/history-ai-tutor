# Промт для доработки: Изначальный тест уровня + выбор классов

## Цель

Добавить в History AI Tutor **изначальный тест уровня (placement test)** и **выбор классов обучения**.
Тест — **по желанию** (ученик может пропустить). Выбор классов — обязательный шаг при первом входе
(или доступный в любой момент из настроек).

---

## 1. Выбор классов обучения

### Требования
- При первом входе пользователь **выбирает, за какие классы он хочет обучаться**.
- Можно выбрать **один класс**, **несколько классов** или **всю базу знаний** (все классы).
- В описании каждого класса **кратко указывать, что изучалось** (см. таблицу ниже).
- Выбор сохраняется в профиле пользователя и используется для:
  - фильтрации тем в Web App (вкладка «Темы»),
  - генерации вопросов практики ОГЭ/ЕГЭ,
  - генерации ежедневных карточек SRS,
  - поиска по базе знаний (RAG) — ограничивать контекст выбранными классами.

### Справочник классов (из базы знаний, `source_file`)

### Реализация
- **API**: `GET /api/classes` — возвращает список классов с кратким описанием и количеством чанков.
- **API**: `POST /api/user/classes` — сохранить выбранные классы (`{"user_id": ..., "classes": [5, 6, 7, 8, 9, 10]}`).
  Пустой массив или `"all"` = вся база знаний.
- **API**: `GET /api/user/classes?user_id=...` — получить выбранные классы.
- **БД**: добавить поле `selected_classes` в таблицу пользователей (JSON-массив или `"all"`).
- **Web App**: при первом входе (если классы не выбраны) показывать экран выбора классов
  с чекбоксами и кнопкой «Вся база знаний». После выбора — переходить к тесту уровня (по желанию) или в главное меню.
- **Бот**: при `/start` (если классы не выбраны) предлагать выбор класса через inline-кнопки.

## 2. Изначальный тест уровня (placement test)

### Требования
- Тест **по желанию**: при первом входе предложить «Пройти тест уровня» или «Пропустить».
- Тест содержит **вопросы по всем годам обучения** (по всем классам из базы знаний).
- Вопросы должны покрывать **все классы** (5–10) и **обе линии** (Всеобщая история и История России).
- По результатам теста сразу выставляется **стартовый уровень 1–5** (сохраняется в профиле).
- Если тест пропущен — уровень остаётся 1 (новичок) и определяется пассивно через `estimate_level`.

### Структура теста
- **10 вопросов** (по 1–2 вопроса на каждый класс 5–10, чтобы покрыть все годы обучения).
- Формат — как в ОГЭ: вопрос + 4 варианта ответа + правильный ответ (для автоматической проверки).
- Вопросы генерируются из базы знаний (RAG) по каждому классу, чтобы тест был релевантен выбранным классам.

### Оценка результата
| Правильных ответов | Стартовый уровень |
|--------------------|-------------------|
| 9–10 | 5 |
| 7–8 | 4 |
| 5–6 | 3 |
| 3–4 | 2 |
| 0–2 | 1 |

### Реализация
- **API**: `GET /api/placement` — получить тест уровня (10 вопросов, по одному на класс).
  Параметр `user_id` — чтобы учесть выбранные классы.
- **API**: `POST /api/placement/submit` — отправить ответы, получить результат и стартовый уровень.
  Тело: `{"user_id": ..., "answers": [{"question_id": ..., "answer_index": ...}, ...]}`.
  Ответ: `{"score": 7, "level": 4, "rank": "..."}`.
- **Сервис**: `services/placement_service.py` — генерация теста, проверка ответов, расчёт уровня.
- **БД**: сохранить результат теста (уровень, дата, количество правильных) в таблице пользователей
  или отдельной таблице `placement_results`.
- **Web App**: экран теста уровня с прогресс-баром (вопрос X из 10), кнопками вариантов,
  экраном результата с уровнем и рекомендацией.
- **Бот**: команда `/test` или inline-кнопка «Пройти тест уровня».

## 3. Интеграция с существующим кодом

### Файлы, которые нужно изменить
- `database.py` — поле `selected_classes` у пользователя, таблица `placement_results` (если нужна).
- `services/adaptive_service.py` — `estimate_level` должен учитывать результат placement-теста
  (если тест пройден — использовать его уровень как стартовый).
- `services/knowledge_service.py` — `get_topics()` должен принимать фильтр по классам.
- `services/exam_service.py` — генерация вопросов с учётом выбранных классов.
- `services/rag_service.py` — поиск с фильтром по классам (если применимо).
- `bot_webhook.py` — новые endpoints `/api/classes`, `/api/user/classes`, `/api/placement`,
  `/api/placement/submit`; команды бота для выбора классов и теста.
- `templates/webapp.html` + `static/webapp.js` + `static/webapp.css` — экраны выбора классов
  и теста уровня.

### Важно (защита от зацикливания)
1. **Не создавать циклов**: тест уровня — одноразовый шаг при первом входе. После прохождения
   или пропуска — сразу переход в главное меню. Не предлагать тест повторно при каждом входе.
2. **Не блокировать доступ**: если пользователь пропустил тест и не выбрал классы — использовать
   «всю базу знаний» по умолчанию и уровень 1. Приложение должно работать без этих шагов.
3. **Не переписывать существующую логику**: `estimate_level` продолжает работать как раньше,
   но если есть результат placement-теста — использовать его как стартовый уровень.
4. **Проверять каждый шаг**: после каждого изменения запускать `python -m unittest test_services`
   и проверять API через curl.

## 4. Критерии приёмки

- [ ] `GET /api/classes` возвращает 6 классов (5–10) с кратким описанием и количеством чанков.
- [ ] `POST /api/user/classes` сохраняет выбор; `GET /api/user/classes` возвращает его.
- [ ] При первом входе в Web App показывается экран выбора классов (можно выбрать несколько или «всю базу»).
- [ ] После выбора классов предлагается тест уровня (можно пропустить).
- [ ] `GET /api/placement` возвращает 10 вопросов, покрывающих все классы 5–10.
- [ ] `POST /api/placement/submit` возвращает score и стартовый уровень по таблице оценки.
- [ ] Уровень из теста сохраняется и используется как стартовый в `estimate_level`.
- [ ] Темы в Web App фильтруются по выбранным классам.
- [ ] Все 21+ существующих тестов проходят; добавлены новые тесты для placement и выбора классов.
