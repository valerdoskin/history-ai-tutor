## 1. Проект и его цель

**Что это:** ИИ-репетитор по истории для подготовки российских школьников к ОГЭ и ЕГЭ.

**Ключевой принцип (НЕ НАРУШАТЬ):** ИИ отвечает **только на основе локальной базы знаний**
(учебники, которые мы отпарсили). Никаких галлюцинаций и внешних источников.
LLM используется для генерации заданий/дистракторов/метаданных, но ответы ученику
всегда опираются на тексты учебников из `knowledge/chunks.json`.

**Архитектура (кратко):**
- Flask-сервер (`bot_webhook.py`) — API + Telegram Web App интерфейс.
- RAG-поиск по локальной базе знаний (Qdrant + эмбеддинги `intfloat/multilingual-e5-large`).
- LLM: DeepSeek (`deepseek-chat`) с fallback на Groq (`llama-3.1-8b-instant`).
- Банк вопросов ОГЭ/ЕГЭ (`knowledge/question_bank.json`) — основной источник заданий.
- Тест уровня (`placement_service.py`), адаптивная система (`adaptive_service.py`),
  практика ОГЭ/ЕГЭ (`exam_service.py`).

## 9. Принципы работы (защита от зацикливания)

1. **Каждый шаг — с чётким критерием завершения.** Если критерий не достигнут после 1-2
   попыток — фиксируем результат и переходим к следующей гипотезе, не крутимся.
2. **LLM — только с fallback.** При ошибке/некорректном ответе возвращаем исходные данные.
3. **Не перепарсиваем всё заново.** Только проблемные книги (через `--only`).
4. **Не трогаем работающий код.** Изменения точечные, в конкретных файлах.
5. **Проверка — разовая, по чек-листу**, не чаще, чем просит пользователь.
6. **Согласовывать каждое действие с пользователем**, не зацикливаться на диагностике.
7. **Все сгенерированные LLM задания сохраняются и переиспользуются** (в question_bank.json),
   не генерировать одно и то же заново.
8. **НЕ выдумывать данные** — всё должно опираться на тексты учебников в chunks.json.
9. **НЕ перечитывать PDF/chunks.json повторно** — извлекать данные за один проход скриптом.
