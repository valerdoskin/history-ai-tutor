## 1. Проект и его цель

**Что это:** ИИ-репетитор по истории для подготовки российских школьников к ОГЭ и ЕГЭ.

**Ключевой принцип (НЕ НАРУШАТЬ):** ИИ отвечает **только на основе локальной базы знаний**
(учебники, которые мы отпарсили). Никаких галлюцинаций и внешних источников.
LLM используется для генерации заданий/дистракторов/метаданных, но ответы ученику
всегда опираются на тексты учебников из `knowledge/chunks.json`.

**Архитектура (кратко):**
- Flask-сервер (`bot_webhook.py`) — API + Telegram Web App интерфейс.
- RAG-поиск по локальной базе знаний (Qdrant + эмбеддинги `intfloat/multilingual-e5-large`).
- LLM: DeepSeek (`deepseek-chat`) с fallback на Groq (`llama-3.1-8b-instant`).
- Банк вопросов ОГЭ/ЕГЭ (`knowledge/question_bank.json`) — основной источник заданий.
- Тест уровня (`placement_service.py`), адаптивная система (`adaptive_service.py`),
  практика ОГЭ/ЕГЭ (`exam_service.py`).

## 9. Принципы работы (защита от зацикливания)

1. **Каждый шаг — с чётким критерием завершения.** Если критерий не достигнут после 1-2
   попыток — фиксируем результат и переходим к следующей гипотезе, не крутимся.
2. **LLM — только с fallback.** При ошибке/некорректном ответе возвращаем исходные данные.
3. **Не перепарсиваем всё заново.** Только проблемные книги (через `--only`).
4. **Не трогаем работающий код.** Изменения точечные, в конкретных файлах.
5. **Проверка — разовая, по чек-листу**, не чаще, чем просит пользователь.
6. **Согласовывать каждое действие с пользователем**, не зацикливаться на диагностике.
7. **Все сгенерированные LLM задания сохраняются и переиспользуются** (в question_bank.json),
   не генерировать одно и то же заново.
8. **НЕ выдумывать данные** — всё должно опираться на тексты учебников в chunks.json.
9. **НЕ перечитывать PDF/chunks.json повторно** — извлекать данные за один проход скриптом.

## 13. Метод добавления карт из учебников (для классов 6-11) — ГЛАВНЫЙ РАБОЧИЙ ПРОЦЕСС

> **Цель:** расширить количество карт с изображениями на остальные учебники (6-11 классы).
> Метод отработан на 5 классе (раздел 4.11) и применён к 6 классу «История России» (раздел 4.12).
> Пользователь **сам вырезает карты** из PDF-учебников и кладёт JPG-файлы в папку `map_preview/<класс>/`.
> Агент добавляет их в проект.
>
> **ВАЖНО (урок из 6 класса):** исторические карты могут быть вынесены в ПРИЛОЖЕНИЕ учебника,
> а не в параграфы. Сначала определить, где находятся карты (в параграфах или в приложении), и найти
> в тексте параграфов ссылки «см. карту N» / «см. Приложение», чтобы понять, к каким параграфам
> привязать карту. Если карта упоминается в нескольких параграфах — создавать записи-копии
> (суффикс «(копия N)» в названии, только если копий несколько) с адаптированными под параграф
> `description`/`key_objects`.

### 13.1. Роли пользователя и агента

| Кто | Что делает |
|-----|-----------|
| **Пользователь** | Вырезает карты из PDF-учебника, кладёт JPG в `map_preview/<класс>/`, сообщает физические номера страниц (страница по содержанию = физическая + 2) |
| **Агент** | Конвертирует JPG → PNG в `static/maps/`, добавляет записи в `maps.json`, генерирует map-вопросы через LLM, проверяет API |

### 13.2. Пошаговый процесс (для каждого класса)

**Шаг 1. Пользователь кладёт карты.** JPG-файлы в `map_preview/<класс>/`. Имя файла = физический
номер страницы (например, `7.JPG` = физическая страница 7).

**Шаг 2. Определить, где находятся карты.** Карты могут быть внутри параграфов ИЛИ вынесены в
ПРИЛОЖЕНИЕ учебника (как в 6 классе «История России», стр. 235-239). Схемы внутри параграфов — это
НЕ всегда исторические карты. Уточнить соответствие страниц (печатная = физическая + 1 = PDF-индекс + 2).

**Шаг 3. Найти упоминания карт в тексте.** Для каждой карты найти в тексте параграфов ссылки
«см. карту N» / «см. Приложение» и определить, к каким параграфам карта относится. Если карта
упоминается в нескольких параграфах — она нужна каждому из них (см. Шаг 5 про копии).

**Шаг 4. Конвертировать JPG → PNG.** Скопировать/конвертировать файл в `static/maps/<slug>.png`
(имя = латинский slug названия карты, например `stoianki.png`).

**Шаг 5. Добавить запись(и) в maps.json.** Для каждого параграфа, где карта упоминается, добавить
запись с полем `image: "/static/maps/<slug>.png"`. Если карта нужна нескольким параграфам — создать
отдельные записи-копии с суффиксом «(копия N)» в названии (только если копий несколько) и адаптировать
`description`/`key_objects` под каждый параграф.
**ВАЖНО:** в `source_chunk_id` разделитель между § и названием параграфа — ТАБУЛЯЦИЯ `\t`, а НЕ пробел.
Если запись уже существует в maps.json (например, карта уже была в списке), просто добавить поле `image`.

**Шаг 6. Сгенерировать map-вопросы через LLM.** Запустить `scripts/pregen_map_questions.py` для записей
с image (можно фильтровать по классу через `--class N`). Скрипт находит текст параграфа по source_chunk_id,
генерирует вопрос через LLM (DeepSeek → Groq), сохраняет в question_bank.json с полем `image`.
Скрипт пропускает записи, для которых вопрос уже есть в банке.

**Шаг 7. Перезапустить сервер.** Сервер кэширует question_bank.json в памяти при старте
(`_question_types_cache`). Без перезапуска новые вопросы НЕ появятся в API.

**Шаг 8. Проверить API.** `/api/exam?qtype=map&classes=<N>` и `/api/train?qtype=map&classes=<N>`
должны возвращать новые карты. Проверить, что статические файлы карт доступны (HTTP 200).

### 13.5. Правила против зацикливания (критически важно)

1. **Один шаг за раз.** Выполнять ровно один шаг процесса, затем останавливаться и сообщать результат.
2. **Не повторять одно и то же действие.** Если действие уже выполнено и дало результат — не выполнять снова.
3. **Не задавать один и тот же вопрос дважды.** Если пользователь уже ответил — использовать ответ и двигаться дальше.
4. **Критерий завершения шага.** Каждый шаг завершён, когда получен конкретный результат (файл создан, данные обновлены).
5. **Точка остановки для вопроса пользователю.** Останавливаться и спрашивать только если нужен ответ человека
   (где находится карта) или возникла неоднозначность.
6. **Не исследовать без цели.** Каждое действие должно приближать к конкретному результату текущего шага.
7. **Фиксировать прогресс.** После каждого завершённого шага кратко записывать, что сделано и что будет дальше.
